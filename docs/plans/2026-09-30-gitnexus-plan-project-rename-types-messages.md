## 1. Objective

[verified] Replace repository-owned StoreX names with `metastorage` across app branding, workspace package scopes, code identifiers, configuration, persistence prefixes, docs, seeds, and test fixtures. [verified] Extract every TypeScript `interface` from implementation/business files into dedicated type-only files, preserving declarations already located in dedicated type/declaration files. [inferred] Centralize literal response/error messages in feature-scoped message constants without changing response codes, status codes, wording, or business behavior.

Acceptance criteria:
- No unintended `storeX`, `Storex`, `storex`, or `@storex` remains in repository-controlled source/config/docs/fixtures; explicit tooling/repository-location exceptions are recorded in §12.
- Workspace package names and all in-repository import/config references agree on `@metastorage/*`; lockfile is regenerated by Bun.
- All interface declarations are in dedicated `*.types.ts`, `types.ts`, or declaration files; no interfaces remain in business/service/repository/UI implementation files.
- Production response/error text is referenced from feature-scoped constants, not inline literals.
- Existing behavior and API error codes/status remain unchanged.
- Changes are committed in small logical commits, normally no more than 8 tracked paths each; no commit mixes unrelated interface/message domains.

## 6. Proposed Changes

1. [verified] Project identity: change root and workspace package names/scopes and every in-repository consumer; rename `StorexApiClient` and `createStorexApiClient` to `MetastorageApiClient` and `createMetastorageApiClient`; set user-facing brand and API metadata to `metastorage`; change app scheme/cookie/storage/local mock DB prefixes and database defaults. Regenerate `bun.lock` with Bun. Do not change schemas, tables, or migrations.
2. [verified] Repository-owned text/config/docs/skill content: update README, AGENTS, docs, fixture/seed descriptions and `.codex/skills/storex-*` paths. Replace demo `@storex.vn` identities with `@metastorage.test`, consistently in seeds/tests. Do not rewrite immutable Git history or historical external issue links.
3. [verified] Type separation: move every interface out of business and mixed-purpose files to adjacent `*.types.ts`/feature `types.ts`; import with `import type` and re-export through existing public barrels. Put Fastify module augmentations into a dedicated `.d.ts` types file. Existing dedicated interface/type declaration files remain the home of their declarations.
4. [verified] Message centralization: add feature-scoped `*.messages.ts` constants for API response text, domain error text, inline `Error` messages, UI error/fallback messages and response descriptions in Swagger. Preserve the exact existing text initially, including dynamic interpolation. Keep codes, statuses, log-only text and test assertion fixtures separate; tests should still assert observable behavior, not import production messages to restate them.
5. [inferred] Do not rename the current filesystem workspace directory or Git remote: the new remote URL is not supplied, and changing either is an external/workspace operation. Keep GitNexus's actual repo locator accurate until the workspace is moved/renamed. This is the only unresolved naming boundary.
6. [inferred] Batch commits by domain and keep each normally at ≤8 paths; package namespace updates may need coordinated consumer batches. Before every commit, run GitNexus detect-changes and stage only the intended batch.

## 7. Implementation Sequence

1. Rename brand-only text and skill directory paths in small documentation/UI batches; preserve actual historical issue URLs and current workspace locator.
2. Rename app/runtime identifiers and database defaults (scheme, auth cookie/storage, local mock DB key, default DB name); update the deep-link tests to assert the new value. No compatibility alias or data migration.
3. Rename package manifests and consumer imports in package/app batches, rename exported API-client identifiers with GitNexus rename after dry-run review, then regenerate Bun lockfile. The three d=1 callers from §4 must all be updated.
4. Extract shared/contracts/API-client/worker interfaces to type-only files; update public exports and run type checks.
5. Extract API module/component interfaces by feature; keep Fastify declaration merging valid; type-check after each area.
6. Add feature-scoped message constants and replace inline response/error message literals by API/UI feature groups; preserve exact values. Update existing test fixtures only when names/imports change.
7. Run repository-wide checks, verify no stale project identifiers/interfaces/production message literals remain, inspect GitNexus graph impact, and commit the last small batches.
